# Pinpoise

A daily balancing game. Five objects, one attempt per object, a new seeded collection each day. Archive, Stats and Settings are retained; practice is removed.

## Develop

```sh
npm ci
npm run dev
npm test
npm run build
```

Development: http://127.0.0.1:5174. Build output: dist/. Tests: jsdom plus native canvas. Use a modern Node release supported by Vite 6; verified with Node 26.4.0.

Generator versions are date-bound. Do not change a released recipe: the first three puzzles use v1/v2. From October 24, 2026, v4 draws five new silhouettes daily from a frozen 6,000-form catalogue, through February 4, 2030 inclusive (1,200 days). No modulo cycling. The app keeps Archive, Stats and Settings available when the catalogue ends, and asks for a new edition instead of repeating shapes.

`src/forms-v4.ts` is immutable released data. `scripts/build-catalogue.mjs` documents its deterministic construction; do not regenerate or reorder a released version. Each connected cell arrangement is unique under translation, rotation and reflection. Angular, chamfered and curved contours are generated by `src/unique.ts`, with clipped material regions that cannot change the silhouette. Tests independently compare all final vector contours under arbitrary rotation, reflection, translation and uniform scale, plus rendered silhouette masks against one another and the 15 historical shapes. Similar-looking forms are possible; the promise is no repeated geometry, not that every shape belongs to a different recognizable object category. Archive review and the unscored home demonstration intentionally remain repeatable.

To extend the schedule, append a new date-bound catalogue without changing existing IDs or contours. Check new silhouettes against every earlier catalogue before publishing. Store validates saved results against their dated recipe.

Scores, streaks and settings remain browser-local, so playing never requires an account. Production can also submit one anonymous result per browser and puzzle to a Cloudflare D1 database. The result screen only reports a percentile once at least 10 real scores exist for that puzzle.

### Cloudflare score database

The Pages project root must be `Source`, with `npm run build` as the build command and `dist` as the output directory.

1. In Cloudflare, create a D1 database named `pinpoise-scores`.
2. Open its Console and run `migrations/0001_scores.sql`.
3. Open the Pinpoise Pages project, then go to Settings, Bindings and add a D1 binding.
4. Use `SCORES` as the variable name and select `pinpoise-scores`.
5. Redeploy the site so the Function receives the binding.

The API stores a one-way hash of a random per-browser identifier. It does not store names, email addresses or IP addresses. Optional account syncing is intentionally separate from this anonymous ranking layer.

Set VITE_SITE_URL for public canonical/Open Graph URLs before deploying to HTTPS. Copy captures the displayed results sheet as a PNG and writes it directly to the clipboard; image clipboard support varies by browser.
